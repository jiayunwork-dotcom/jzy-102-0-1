做地理科普可视化的团队想要一个能在浏览器里直接摆弄的地形生成小工具，用来演示雨水是怎么把光秃秃的隆起地表一点点冲刷出河谷和沟壑的。要求是真的跑一遍侵蚀物理过程，不是放一段预渲染动画糊弄过去，而且演示者要能现场改参数、点一下按钮，看着山脊在眼前慢慢被啃出沟来。

地形先由噪声算法生成一片高度场：多层不同频率的噪声叠加起来（每叠加一层，频率按固定倍数升高、振幅按固定比例衰减），形成有主体起伏又带细节的地表，网格分辨率、层数、频率倍增系数、振幅衰减系数都要能从前端传给后端调节。生成好的高度场交给水力侵蚀模拟：把地表想象成会承接雨滴的网格，每一颗雨滴落在随机位置，沿着当前脚下坡度最陡的方向往下滑，边滑边根据坡度和自身携带能力判断该从地面带走一点泥沙还是该把身上超出承载量的泥沙沉积下来，速度随下滑高度差累积，水量随路程慢慢蒸发，滑到水量耗尽或者步数耗尽就消亡，换下一颗雨滴重新开始。这批雨滴模拟完一轮之后，地表应该能看出被冲出浅浅水系的痕迹，山脊变尖、低地淤积。

后端核心要锁死几条关系，并且要能被自动化测试直接验证：只放大侵蚀率参数、不改别的，同样一批雨滴、同样的随机种子跑完之后，地表总体的高度方差应当比侵蚀率调小时更大（冲刷更狠，起伏被拉得更剧烈）；固定随机种子不变、只重复跑同一组参数两次，两次得到的高度场必须完全一致，不允许侵蚀模拟里混入未受种子控制的随机性；只把噪声层数调多，地形的高频细节应该增多，用地表梯度的整体波动幅度衡量应当上升而不是下降；雨滴的水量必须严格随路程单调不升，一旦触发蒸发到阈值以下就必须让该雨滴终止，不能出现雨滴水量耗尽了却还在继续侵蚀地面的情况；侵蚀与沉积必须满足局部质量整体守恒，一轮模拟前后整张高度图的总高度和只能因为沉积/侵蚀相互抵消而发生极小的浮点误差量级的变化，不能無故整体上升或下降。

参数非法的情况要在计算之前挡住：分辨率超出允许范围、层数或振幅衰减系数不在合理区间、侵蚀相关的速率参数为负，都要带原因用错误响应打回去，不能让后端跑到中途才因为除零或者数组越界崩掉。后端另外要支持把当前高度场结果连同这一轮用的参数一起存成一个命名快照，前端可以拉取快照列表、取某一个快照的高度数据重新在画面里摆出来，快照另存不要求持久化到会话之外，进程重启丢失也可以接受，但同一进程运行期间要能稳定存取。

前端用三维网格把后端算好的高度数据渲染成起伏地表，相机支持旋转缩放平移查看，光照从一个可调角度的方向光打过来，地形随高度和坡度做基础的分层着色（低处偏一种颜色、高处偏另一种颜色，陡坡再单独一种颜色），无需做贴图纹理这么精细。参数调节面板放在页面一侧，包含噪声生成的几个参数滑块和侵蚀模拟的几个参数滑块，改完参数点生成按钮把请求发给后端拿新高度场，点侵蚀按钮就在当前高度场基础上追加跑一轮侵蚀并刷新画面。快照另存与快照加载各给一个简单入口即可，不必做成复杂的版本管理界面。

前后端职责按模块拆开：噪声生成、侵蚀模拟核心、快照存取、参数校验各自独立成后端模块文件，前端的三维渲染、参数面板、与后端的请求交互也各自拆成独立的组件文件，避免把噪声算法和侵蚀算法糅进同一个巨大文件里连读都费劲。快照只是把一份高度数组和参数原样存进内存里按名字取回，不涉及事务日志或恢复机制，实现上一个简单的键值存取类即可，不必单独展开成重内核。后端选 Java 17 配 Spring Boot 搭接口层，前端选 Vue 3 配 Three.js 做三维渲染、用 Vite 构建。仓库整体用 Docker Compose 一并拉起前后端两个服务，暴露一个页面地址即可访问；随仓库带自动化测试锁住后端的核心不变量，重点覆盖侵蚀率变化引起高度方差变化、固定种子结果可重现、质量守恒这三条。
